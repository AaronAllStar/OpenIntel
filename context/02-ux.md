# OpenIntel — UX Guidelines

## UX objective

Make complex OSINT workflows feel like a simple investigation application.

The interface should hide implementation complexity while preserving transparency about where evidence came from.

## Main flow

```text
Dashboard
   ↓
New Investigation
   ↓
Target
   ↓
Investigation Type
   ↓
Start
   ↓
Investigation Progress
   ↓
Results
```

## New Investigation

The default interface should look approximately like:

```text
What do you want to investigate?

[ username / email / domain / URL ]

Type:

[ Username ]
[ Email ]
[ Domain ]
[ Website ]

[ Start Investigation ]
```

Do not initially expose:

```text
Sherlock
Maigret
SpiderFoot
Photon
Recon-ng
theHarvester
```

The application chooses appropriate engines automatically.

## Investigation progress

Never show a confusing terminal-style wall of logs as the primary interface.

Instead:

```text
Investigation in progress

✓ Target validated
✓ Username discovery
✓ Profile analysis
● Relationship analysis
○ Report generation
```

Advanced users can expand technical execution details.

## Results

Present findings in layers.

### Overview

```text
42 entities
17 relationships
8 sources
3 high-confidence associations
```

### Entities

Cards or tables grouped by type:

```text
Profiles
Emails
Domains
Repositories
URLs
IPs
Organizations
```

### Evidence

Every important result must show:

```text
What was found
Source
Timestamp
Tool
Confidence
```

### Relationships

Use readable language.

Prefer:

```text
"A relationship was found between X and Y"
```

rather than exposing raw database terminology.

## Confidence

Avoid presenting inferred associations as facts.

Use labels such as:

```text
Observed
Supported
Potential association
Strong association
```

Always allow the user to inspect the underlying evidence.

## Graph

The graph should support:

* zoom
* search
* filtering
* entity selection
* relationship inspection
* source inspection

Do not overload the graph with every piece of raw data by default.

## Advanced mode

Advanced users may access:

```text
Selected engines
Execution settings
Rate limits
Concurrency
Scope
Raw results
Technical logs
```

These controls should not clutter the default workflow.

## UX principles

* Minimize cognitive load.
* Prefer sensible defaults.
* Explain errors in human language.
* Avoid unnecessary configuration.
* Make system activity visible.
* Never hide evidence provenance.
* Never make inference look like certainty.
* Allow users to progressively explore deeper technical details.
